### 배경과 목적
이번 목표는 금형별 이력 탭을 "언제, 어느 부위를, 왜, 얼마나 바꿨는지"를 한 화면에서 찾는 기능으로 키우는 것입니다. 찾은 이력은 3D 형상 위에서 바로 위치를 확인할 수 있어야 합니다.
실무에서는 설계변경, 치수수정, 수리 이력이 불량 원인 추적, 재수정 판단, 외주·이관 검토 때 계속 필요합니다. 그런데 이 기록은 엑셀, 메일, 도면 리비전, 담당자 기억에 흩어져 있기 쉽습니다. 그래서 같은 부위를 또 고치거나, 이전 변경 사유를 몰라 판단이 늦어집니다.
이 기능이 풀 문제는 세 가지입니다.
- 금형 하나의 과거 이력을 시간순으로 한눈에 본다
- 설계변경·치수수정은 변경 전과 후, 사유를 구조화해서 남긴다
- 이력을 3D 형상의 부위와 연결해, 어디를 몇 번 고쳤는지 보이게 한다
### 현재 상태와 범위
조장이 만든 3D 대시보드는 그대로 두고, 이 문서의 모듈을 필요한 만큼 붙입니다. 두 화면을 잇는 열쇠는 3D 부품 이름(part_id)과 금형번호(mold_id)입니다.
- 구분 · 내용 · 이번 작업
- 3D 도면 업로드·표시 · 금형 3D 도면을 넣으면 형상으로 보여 줌 (조장) · 유지. 부품 이름 규칙만 맞춤
- 냉각 흐름·수지 유동 · 냉각수 흐름, 사출 시 수지가 채워지는 모습 (조장) · 유지. M7 단면은 선택
- 형개폐·이젝터·취출 · 금형 작동 순서 애니메이션 (조장) · 유지
- 금형별 이력 정리 · 금형마다 이력을 정리해 보여 줌 (조장) · 확장: M1, M6
- 이력 ↔ 3D 부위 연결 · 없음 · 신규: M2
- 노후도·수리 vs 재제작 판단 · 없음 · 신규: M3
- 금형 목록·설비 호환 · 없음 · 신규: M4
- 제품 3D·금형 연동 · 없음 · 신규: M5
조장 대시보드의 이력 기능이 어떤 필드를 어디에 저장하는지는 아직 확인하지 못했습니다. 아래 데이터 구조는 기존 필드에 더하는 방식으로 맞추면 됩니다.
### 사용자와 사용 장면
주 사용자는 사출 운영 담당자와 금형 담당자입니다. 두 사람 모두 "이 금형, 전에 뭘 고쳤지?"를 1분 안에 답할 수 있어야 합니다.
- 장면 · 누가 · 필요한 이력 · 쓰는 모듈
- 제품에 치수·외관 불량이 났다 · 사출 운영, 품질 · 불량 부위를 만드는 금형 부위의 최근 수정·수리 · M5 → M2 → M1
- 설계변경 요청이 들어왔다 · 금형 담당 · 같은 부위의 이전 변경과 사유, 현재 도면 Rev · M1, M6
- 같은 부위를 또 고치려 한다 · 금형 담당 · 수정 횟수, 누적 수리비, 재제작 견적 대비 · M2, M3
- 금형 이관·외주·재투자를 검토한다 · 사출 운영 · 노후도, 호환 설비, 외주 업체별 비용 · M3, M4
- 담당자가 바뀌어 인수인계한다 · 금형 담당 · 금형별 전체 타임라인과 도면·사진 · M1, M6
### 모듈별 상세
### M1 이력 타임라인·등록 (기본 모듈)
금형 하나의 이력을 최신순 카드로 보여 주고, 유형을 고르면 그 유형의 칸만 나오는 폼으로 등록합니다. 다른 모듈은 모두 이 모듈의 데이터를 씁니다.
- 카드: 유형(색), 내주·외주 표시, 일자, 3D 부위, 외주 업체명, 비용, 상태, 치수·첨부 개수. 펼치면 사유, 원인, 조치, 치수 전후 표, 첨부
- 필터: 유형 6종, 내주·외주, 검색(제목·사유·업체), 3D 부위
- 유형 6종: 설계변경, 치수수정, 수리, 점검, 이관, 기타(이름 직접 입력, 한 번 쓴 이름은 목록에 저장)
- 작업 구분: 내주는 사내 작업 부서, 외주는 업체명 필수. 쓴 업체명은 다음부터 목록으로 제안
- 비용: 금액(원)과 부담처(사내·업체·고객)
- 복사 등록: 예전 카드의 부위·업체·사유·측정 부위를 복사하고 날짜·치수·비용만 고침
- 다른 모듈 갱신: 점검에 누적 쇼트를 넣으면 금형 쇼트가 바뀌고(M3 노후도), 이관을 저장하면 현재 설비가 바뀝니다(M4)
- 완료 기준: 등록 후 새로고침해도 남고, 외주인데 업체명이 없으면 저장되지 않음
### M1 · 유형별 입력 항목
모든 유형에 공통으로 일자, 제목, 사유, 3D 부위, 작업 구분(내주·외주)과 업체·부서, 담당자, 비용과 부담처, 상태, 첨부가 들어갑니다. 유형별로 아래 항목이 더해집니다.
- 유형 · 추가 항목
- 설계변경 · 변경 요청 번호(ECO), 요청 부서, 변경 전 Rev → 변경 후 Rev, 변경 내용, 적용 시작일
- 치수수정 · 측정 부위별 변경 전 값, 변경 후 값, 공차(단위 mm), 수정 방법(가공·용접 등), 수정 후 제품 측정 결과
- 수리 · 고장 증상, 원인, 조치 내용, 수리처, 수리 기간, 견적·정산 금액
- 점검 · 점검 항목, 결과(양호·주의·불량), 누적 쇼트 수
- 이관 · 보낸 곳, 받는 곳, 사출기 호기, 이관 사유
- 기타(사용자 정의) · 유형 이름 직접 입력(예: 세척, 부품 교체, 시사출, 보관 위치 변경), 자유 메모. 한 번 만든 유형 이름은 목록에 저장
치수수정은 한 번에 여러 부위를 고칠 수 있으므로, 측정 부위를 행으로 추가하는 작은 표 형태로 입력받습니다.
### 데이터 구조
데이터는 금형(Mold), 이력(HistoryEvent), 치수 변경(DimensionChange), 첨부(Attachment) 네 가지입니다. 이력 하나에 치수 변경과 첨부가 여러 개 붙습니다. 3D와 연결하는 필드는 part_id와 position 두 개입니다.
### Mold (금형)
- 필드 · 타입 · 설명
- mold_id · 문자 · 금형번호, 기본 키
- part_no / part_name · 문자 · 품번, 품명
- cavity · 숫자 · 캐비티 수
- machine_tonnage · 숫자 · 적용 사출기 톤수
- maker / made_on · 문자 / 날짜 · 제작처, 제작일
- current_rev · 문자 · 현재 도면 Rev
- total_shots · 숫자 · 누적 쇼트 수
- model_file · 문자 · 기존 3D 대시보드의 모델 파일 경로
### HistoryEvent (이력)
- 필드 · 타입 · 설명
- event_id · 문자 · 기본 키
- mold_id · 문자 · 어느 금형의 이력인지
- type · 목록 · design_change / dimension_fix / repair / inspection / transfer / other
- type_label · 문자 · type이 other일 때 사용자가 쓴 유형 이름(예: 세척)
- date · 날짜 · 작업 완료일(진행 중이면 요청일)
- title / reason / detail · 문자 · 제목, 사유, 상세 내용
- owner / vendor · 문자 · 담당자, 작업 업체
- cost · 숫자 · 비용(원), 없으면 비움
- cost_payer · 목록 · internal / vendor / customer (비용 부담처)
- rev_before / rev_after · 문자 · 설계변경 때 도면 Rev
- part_id · 문자 · 3D 모델의 부품(메시) 이름 또는 ID
- position · x, y, z · 3D 핀 좌표(부품을 고를 수 없을 때)
- status · 목록 · requested / in_progress / done
- extra · 객체 · 유형별 추가 항목(F2 표)
### DimensionChange (치수 변경) · Attachment (첨부)
- 필드 · 타입 · 설명
- event_id · 문자 · 연결된 이력
- point_name · 문자 · 측정 부위명
- before / after / tolerance · 숫자 · 변경 전, 변경 후, 공차(mm)
- file_type · 목록 · drawing / photo_before / photo_after / report
- file / rev · 문자 · 파일 경로, 도면 Rev

### 화면 구성
이력 탭은 왼쪽 3D 형상, 오른쪽 타임라인, 아래 등록 폼으로 나눕니다. 3D는 기존 대시보드 화면을 그대로 쓰고, 핀과 강조 표시만 더합니다.
금형 이력 탭 화면 배치 · 영역 4개
파란 화살표 두 개가 이번에 새로 만드는 연결입니다. 카드를 누르면 3D 부위가 강조되고, 부위를 누르면 타임라인이 그 부위 이력만 남깁니다.
### 해커톤 우선순위
해커톤에서는 1단계만 끝내도 데모가 됩니다. 저장은 팀원이 지금 쓰는 방식을 그대로 쓰고, 없다면 JSON 파일이나 SQLite처럼 가장 가벼운 것을 씁니다.
- 단계 · 만들 것 · 이유
- 1단계 · 꼭 · 데이터 구조, F1 타임라인, F2 등록 폼(설계변경·치수수정·수리·기타), F3 3D 부위 연결, F8 비용 입력과 누적 합계, F9 기타 유형, 샘플 데이터 금형 1벌 · 이력과 3D가 이어지는 장면이 데모의 핵심. 비용·기타 유형은 필드 몇 개라 부담이 작음
- 2단계 · 시간 되면 · F4 검색·필터, F5 반복 수정 표시, F6 첨부와 전후 사진, 점검·이관 유형 · 실무에서 쓸 때 바로 필요한 것
- 3단계 · 다음 · F7 AI 요약, 사출기 호기·쇼트 수 자동 연동, 등록 승인 흐름, 사내 시스템 연동 · 해커톤 이후 실제 도입 때
F3은 두 가지 방식 중 하나로 만듭니다. 3D 모델이 부품별로 나뉘어 있으면 부품 클릭(part_id)이 가장 쉽고, 하나로 합쳐져 있으면 클릭한 지점에 핀 좌표(position)를 남깁니다.
### 데모 시나리오와 완료 기준
데모는 "불량이 났다 → 이력을 찾는다 → 같은 부위를 여러 번 고쳤다는 걸 3D에서 본다" 흐름으로 3분 안에 보여 줍니다.
- 금형 목록에서 샘플 금형을 고른다. 기존 3D 형상과 작동 애니메이션이 나온다.
- 이력 탭을 열면 타임라인에 샘플 이력 8~10건이 최신순으로 보인다.
- 치수수정 카드를 누르면 3D에서 그 부위가 강조되고, 변경 전후 치수가 표시된다.
- 3D에서 다른 부위를 누르면 그 부위 이력만 남는다. 여러 번 고친 부위에는 횟수 배지가 보인다.
- 새 치수수정을 등록하고 3D에서 부위를 찍는다. 저장하면 타임라인 맨 위에 바로 나타난다.
완료 기준
- ☒ 샘플 금형 1벌에 이력 8건 이상, 3가지 유형 이상이 들어 있다
- ☒ 타임라인 카드를 누르면 3D 부위가 강조된다
- ☒ 3D 부위를 누르면 타임라인이 그 부위로 걸러진다
- ☒ 등록 폼으로 저장한 이력이 새로고침 후에도 남아 있다
